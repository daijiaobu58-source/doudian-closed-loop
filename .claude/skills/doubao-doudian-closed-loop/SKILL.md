# 抖店电商闭环运营总控（v2）

管理抖店（抖音电商）店铺的六节点闭环，叠加店铺生命周期四阶段与三道决策门。品类无关，任何类目均可使用。本技能为「可直接部署版」：安装后按下方流程即可运行，无需绑定任何特定店铺数据。

## 工作流程概览

1. 读取记忆库（先读后写；文件不存在则从 `assets/memory-template.md` 复制初始化）
2. 确定当前店铺阶段（起号期 0-30 天 / 放量期 31-90 天 / 稳定期 91-180 天 / 清仓迭代期）
3. 路由到节点（默认【选品】）
4. 按节点标准产出（输出标准见 `references/node-output-specs.md`），三道决策门强制检查
5. 每个节点产出后，主动向用户索要真实数据回填记忆库；无真实数据时所有建议标注「假设依据」
6. 对话结束时强制写回记忆库

## 记忆库协议

**读取**：每次对话开始先读取用户项目目录下的《XX店铺_记忆库.md》。

**初始化**：文件不存在时，从 `assets/memory-template.md` 复制生成，并向用户索要 4 项信息（缺什么问什么，不编造默认值）：
1. 类目
2. 价格带
3. 供应链（自有/一件代发/混合）
4. 月推广预算

**结构（v2 升级为五张表）**：
- 店铺信息：类目、价格带、供应链、月预算、体验分
- 爆品表：品名|上架日期|CTR|CVR|UV价值|GPM|退款率|品质退货率|阶段结论
- 复盘表：周期|做了什么|数据结果|流量结构|CTR/CVR|退款率|体验分变化|归因标签|止损线|下一轮选品约束（排除项/必含项）
- 爆品要素库：品名|人群画像|素材类型|价格带|达人类别|佣金率|可复制结论（成功品要素沉淀，选品「必含项」从这里取）
- 失败品黑名单：品名|失败原因|失败阶段|是否可逆|日期

**写回**：每个节点产出后 / 对话结束时强制写回。

**铁律**：
- 无真实数据时，所有建议标注「假设依据」
- 禁止编造店铺后台数据冒充真实
- 所有数字必须来自：用户提供、可复现数据源（巨量算数/罗盘/精选联盟/飞瓜或蝉妈妈）、或明确标注的估算
- 行业基准给不出时标注「需用店铺历史数据校准」，禁止编造基准

## 阶段路由（四阶段打法）

| 阶段 | 周期 | 阶段目标 | 节点权重（高→低） | 考核指标 |
| --- | --- | --- | --- | --- |
| 起号期 | 0-30 天 | 跑通 1-2 个品 + 素材模型 + 体验分≥4.5 | 选品/优化/上架/推广(低)/复盘(3天) | 体验分、3秒完播、商品卡CTR |
| 放量期 | 31-90 天 | 跑出爆品，ROI≥保本×1.3 | 推广/优化/选品/复盘(周) | ROI、日销、退款率 |
| 稳定期 | 91-180 天 | 稳定出单+体验分维持+新品接力 | 选品/优化/推广(中)/复盘(月) | 动销率、体验分、新品通过率 |
| 清仓迭代期 | 随时触发 | 库存出清+止损+沉淀 | 复盘/选品/推广(中) | 库存周转、止损执行率 |

**路由规则**：店铺首次进入=起号期；体验分≥4.5 且跑出首个 ROI≥保本 的品 → 放量期；连续 2 个月稳定 → 稳定期；任一品触发止损线 → 该品进清仓流程。先确认当前阶段，再按该阶段节点权重执行。

## 三道决策门（强制，每节点间检查）

- **门1 选品→上架**：全口径毛利≥15% + ≥2 数据源支撑 + 体验分风险低 + 资质可办 → Go；证据弱但有毛利 → 有条件 Go（只上 1 个测试 SKU）；否则 No-Go 回选品
- **门2 上架→推广**：上架 3-7 天有自然曝光（>0）+ 商品卡 CTR≥2%（经验基准，需校准）+ 无违规/差评异常 → Go；否则先优化（换主图/标题/价格），3 轮无效 → 判品不行回选品
- **门3 推广→复盘**：素材达标（3 秒完播≥30%，需校准）+ ROI≥保本 或 转化率连续上升 + 体验分≥4.5 → 放量 Go；否则缩预算/降佣；连续 2 周期 ROI<保本 → 止损清仓 + 黑名单

## 关键公式（v2 锁定，计算必须走公式）

- **全口径毛利** = 售价 − 货品 − 快递 − 包材 − 平台扣点(1-5%) − 达人佣金(10-30%) − 退货损耗(退款率×单均履约成本) − 预期广告损耗
- **硬淘汰线**：单均毛利 < 售价 15%（或 <8 元）→ 淘汰
- **保本 ROI** = 1 ÷ (1 − 毛利率 − 佣金率 − 扣点 − 退货损耗率 − 广告服务费)
- **目标 ROI** = 保本 × 1.3

## 节点路由

- 新对话默认进入【选品】节点，除非用户指定阶段
- 用户说「进入XX节点」「帮我选品/上架/优化/推广/复盘」等 → 进入对应节点
- 各节点的详细输出标准、动作、放弃条件：见 `references/node-output-specs.md`

## 数据中枢对接（可选，无开发者版）

用户可将飞书多维表格作为记忆库数据中枢（7 张表：店铺信息/候选品池/爆品表/复盘表/爆品要素库/黑名单/每日数据采集）。对接方式：
1. 用户在飞书表格「每日数据采集」填数据（或表单提交），仪表盘自动更新
2. Agent 读表格数据做分析（数据源为表内记录，非编造）
3. 分析结论写回对应表，用户确认后生效
4. 无飞书表格时退回本地记忆库 md 文件模式，两种模式互不冲突
表格字段结构与本地记忆库五张表一一对应，可直接互相迁移。

## 合规红线（每次输出前自动扫描，命中即替换或阻断并提示）

- 极限词：最/第一/100%/纯天然/顶级/国家级等
- 功效宣称：食品禁宣称治疗功效；保健食品需蓝帽子备案；营养品避开保健食品边界用词
- 价格红线：禁止虚构原价/违规划线价
- 诱导红线：禁止"不买就亏/先拍后付"式话术
- 资质红线：报白/证照/检测报告/委托加工协议/进口报关，缺一不上架
- 违禁品类：未经备案保健食品、医疗器械、跨境缺资质商品

## 权限分级（自动执行边界）

- **自动执行**：查询、分析、生成方案
- **必须用户确认**：任何写入店铺后台的动作（上架/改价/投放/发消息）
- **明令禁止**：改评价、删差评、刷单/虚假交易、站外导流、绕过平台规则

## 边界

- 无店铺后台权限，所有数据由用户提供；禁止编造数据冒充真实
- 涉及 API 自动操作（改价、上架、投放）只给方案，不假装已执行
- 数据来源不明的评分/数字一律标注「假设依据」

# 抖店电商闭环运营工作流 · doudian-closed-loop

> 一个**品类无关**的抖店（抖音电商）闭环运营 Agent 技能包：`选品 → 上架 → 优化 → 推广 → 复盘 →（反哺）选品`，叠加店铺生命周期四阶段与三道决策门。纯提示词驱动，零依赖，可部署到豆包、Claude Code、CodeX 或任何支持 Skills/自定义指令的 AI 工具。

## 它解决什么问题

抖店运营最大的痛点不是"不会干活"，而是**流程断链**：选品靠感觉、上架凭经验、投流拍脑袋、复盘走过场，导致每个月的坑重复踩。

这个工作流把资深操盘手的打法固化成一套可执行的闭环：

| 节点 | 核心产出 | 关键把关 |
| --- | --- | --- |
| 选品 | ≥5 个候选品（全口径毛利/竞争度/达人供给/数据来源） | 硬淘汰线：全口径毛利 < 售价 15% 即淘汰 |
| 上架 | 3 组标题 / SKU 三档结构 / 资质清单 / 活动节奏 | 决策门1：毛利达标+数据源够+资质能办才上架 |
| 优化 | 分渠道漏斗四要素诊断（基准/你的数据/差距/动作） | 决策门2：3-7 天无自然流量先优化不投流 |
| 推广 | 3 条短视频脚本 / 千川计划（保本 ROI 倒推）/ 达人话术 | 决策门3：素材达标+ROI≥保本才放量 |
| 复盘 | 目标 vs 结果 / 归因决策树 / 经验沉淀表 / 下一轮方向 | 强制沉淀「排除项+必含项」约束下一轮选品 |

**核心机制**：
- **四阶段打法**：起号期（0-30 天）→ 放量期 → 稳定期 → 清仓迭代期，各节点权重和动作随阶段变化
- **三道决策门**：选品→上架、上架→推广、推广→复盘，每步 Go/No-Go 把关，数据不够就拦下来
- **记忆库**：店铺信息 / 爆品表 / 复盘表 / 爆品要素库 / 失败品黑名单 五张表，AI 先读后写，复盘结论硬约束下一轮选品
- **数据纪律**：无真实数据时所有建议标注「假设依据」，禁止编造店铺后台数据
- **合规红线**：极限词 / 功效宣称 / 价格 / 诱导话术 / 资质 / 违禁品类 六类自动拦截

## 快速开始（3 个平台，选一个）

### 豆包专业版（推荐）
1. 把 `skills/doubao-doudian-closed-loop/` 整个文件夹放进豆包的技能目录（设置-技能 → 技能存放目录）
2. 新开对话，输入：**「用抖店闭环运营工作流」**
3. 回答 4 个初始化问题（类目 / 价格带 / 供应链 / 月预算），即可开始

### Claude Code
```bash
# 在你的项目里
mkdir -p .claude/skills
cp -r .claude/skills/doubao-doudian-closed-loop .claude/skills/   # 或直接 clone 本仓库后运行
# 或在 Claude Code 里用 Add Skill 添加
```
然后在 Claude Code 里输入：**「用抖店闭环运营工作流」**

### CodeX / Codex CLI
```bash
# 在你的项目里
cp AGENTS.md .           # Codex 每次进入项目自动读取
mkdir -p .codex/skills
cp -r .codex/skills/doubao-doudian-closed-loop .codex/skills/
```
然后在 Codex 里输入：**「用抖店闭环运营工作流」**

## 数据纪律与合规边界（务必了解）

- **AI 不会编造你的店铺数据**：它没有你的后台权限。所有数字来自你提供、可复现数据源（巨量算数 / 罗盘 / 精选联盟 / 飞瓜等），或明确标注「假设依据」
- **AI 不能自动执行写操作**：上架 / 改价 / 投放 / 回复消息必须由你在店铺后台操作确认。这是刻意设计的合规边界
- **行业基准需校准**：内置经验基准（如商品卡 CTR≥2%、3 秒完播≥30%）标注「需用店铺历史数据校准」，跑完第一个 30 天用真实数据回写
- **品类无关**：宠物食品、女装、零食、美妆、家居等任何类目复制即用，模板不含品类特定内容
